# Firefox(Gecko) 指纹魔改移植方案

## Context（为什么做这件事）

Chromium 侧的 per-context 指纹定制已完整交付：给 `RendererPreferences` 加一个 `string fingerprint`（JSON blob），靠其 per-WebContents 自动广播到所有 renderer（含跨源 OOPIF 与三种 worker），各 Blink 读取点解析 JSON 覆盖返回值；per-BrowserContext 存储 + 独立 `Fingerprint.setContextOverrides` CDP 域下发；读回面 `readbackSeed` 驱动 murmur 噪声 + 真机 replay；框架 `new_context(fingerprint=)` 一步下发。已在云机编出字节一致产物、检测页 `inconsistencies=0`。

现在要把**同一套能力照搬到 Firefox(Gecko)**：通过 WebDriver BiDi 下发指纹画像，Gecko 各读取点读它、覆盖 UA/WebGL/canvas/audio/screen/locale/timezone 等，遵循同样的「回放 > 噪声(seed) > native」三态；外加 4 个 Firefox 专属反检测点（BiDi 自动化会暴露的特征）。

**已确认的关键事实（Phase 1 三路 Explore + 云机只读侦察）**：
1. Gecko 有等价于 RendererPreferences 的传播机制——**BrowsingContext synced field**（`MOZ_EACH_BC_FIELD`/`FIELD`，parent 设、IPC 自动同步到所有 content 进程）。Playwright 的 Firefox patch 已证「往 BC 加自定义 synced 字段承载覆盖值」是成熟做法。
2. BiDi 完全可扩展，且**已有 `emulation` 模块**（`setTimezoneOverride`/`setLocaleOverride`/`setUserAgentOverride`/`setScreenSettingsOverride`…）——Firefox 版 `moz:fingerprint` 模块 ≈ 照抄它 + 加维度。root 模块跑在 parent 进程、有完整 chrome 特权。
3. RFP(`nsRFPService`) 已把绝大多数读取点选好址，但其值是**固定 canonical + 每会话不可控随机**，无 seed/replay/per-context → **复用 RFP 的选址，不复用其值/随机化，自建注入层**。
4. replay 契约在云机 `~/chromium/src` 完整存在（7 个读回点，`//BROWSER_FINGERPRINT` 标记），值编码见文末附录，实现时直接 1:1 抄。

## 本轮已定的范围决策

- **丢弃 UA-CH**：真实 Firefox 152 不发 `sec-ch-ua`、无 `navigator.userAgentData`（Chromium 专属）。Firefox 画像**不含** `uaPlatform`/`uaBrands`/`uaFullBrands`、不发 sec-ch-ua、不造 userAgentData——发这些反而是破绽。保留 `userAgent` 串 + `navigator.platform`/`oscpu`。
- **v1 含 replay**：读回面做全三态（replay > noise > native）。replay 精确值编码从云机 Chromium 源码逐点读取后 1:1 镜像（本机已有云机权限，已侦察定位）。

## 架构

### 传输骨架（= Chromium 那套的 Firefox 对应物）
```
BiDi moz:fingerprint 模块(root, parent 特权)  ← Python 侧 b.run("moz:fingerprint.setContextOverrides", {fingerprint: <JSON str>})
  → 写入 BiDi SessionData(Services.ppmm.sharedData) —— 覆盖现存+未来所有 frame/worker/新进程 + 持久化
  → 落地为 BrowsingContext 新增 synced field  FingerprintProfile(nsString, JSON blob)  —— parent 设、IPC 自动同步到所有 content 进程；CanSet 限 parent 防篡改
  → C++ 各读取点  bc->GetFingerprintProfile()  解析 JSON，跑「回放 > 噪声 > native」三态
  → Worker(无 BC)：把 BC 字段快照进 WorkerLoadInfo/ClientInfo，随 worker 线程带入（Firefox 专属额外工作量）
```
- 单一 JSON blob 字段（不逐维度拆 BC 字段、也不复用 `customUserAgent` 等既有字段以免语义打架），与 Chromium 契约 1:1、三态逻辑集中。
- 模块模板：`remote/webdriver-bidi/modules/root/emulation.sys.mjs` + `windowglobal/emulation.sys.mjs`；注册 `ModuleRegistry.sys.mjs`（用 `moz` 私有命名空间）+ `jar.mn`。

### 各维度读取点（Gecko 落点，复用 RFP 选址）
| 维度 | 文件 → 读取点 |
|---|---|
| navigator.userAgent / platform / oscpu / hardwareConcurrency / languages | `dom/base/Navigator.cpp`：`GetUserAgent`/`GetPlatform`/`GetOscpu`/`HardwareConcurrency`/`GetLanguages` |
| WebGL UNMASKED vendor/renderer | `dom/canvas/ClientWebGLContext.cpp`：`GetParameter`（可复用原生 pref `webgl.override-unmasked-vendor/-renderer` 作粗覆盖，细粒度走 BC 字段） |
| WebGL 扩展列表 | `ClientWebGLContext`/`WebGLExtensions*`：`GetSupportedExtensions` |
| canvas getImageData / 像素读回 | `dom/canvas/CanvasRenderingContext2D.cpp`：`GetImageBuffer`/`GetImageDataArray`（RFP 的 `RandomizePixels` 注入点，替换为我们的三态） |
| canvas toDataURL / toBlob | `dom/html/HTMLCanvasElement.cpp`：`ToDataURLImpl`/`ToBlob`/`GetImageBuffer` |
| WebGL readPixels | `ClientWebGLContext`/`WebGLContext.cpp`：`ReadPixels`（Firefox 无现成，自建） |
| WebAudio 读回 | `dom/media/webaudio/AnalyserNode.cpp`（`GetFloat/ByteFrequencyData`）+ `AudioContext.cpp`（Offline 渲染 buffer）（Firefox 不加噪，全自建） |
| screen 宽高/深度 | `dom/base/Screen.cpp`：`GetRect`/`GetAvailRect`/`GetColorDepth` |
| timezone | `nsRFPService` 现状是**进程级 `TZ=UTC` 环境变量** → 改为读 BC 字段 + JS 引擎 **per-realm 时区 override**（`nsJSUtils::ResetTimeZone` 路径），自建 per-context 化 |
| locale | `nsRFPService::GetSpoofedJSLocale` 路径 → 改读 BC 字段 |
| referrer | `dom/base/ReferrerInfo.cpp` / `Document::GetReferrer`（仅顶层导航） |

### 4 个 Firefox 专属反检测点（落点已由 Playwright patch 交叉印证）
- **P0-1 webdriver=false**：`Navigator::Webdriver()`（单一读取点，`dom/base/Navigator.cpp`）——画像启用时短路 `return false`。
- **P0-2 visibilityState="visible"**：`Document::VisibilityState()`/`Hidden()` 读 `mVisibilityState`；让 `UpdateVisibilityState` 在画像启用时恒为 Visible。
- **P0-3 hasFocus()=true + hidden=false**：`Document::HasFocus()` 走 `IsActive() && mDocumentContainer->ShouldOverrideHasFocus()`；接 `nsDocShell` 位域 `mOverrideHasFocus`（Playwright 新增）+ `nsFocusManager` 补焦点事件/抑制 blur。**四处（hasFocus/hidden/visibilityState/blur）同源判定**，避免自相矛盾。
- **P1-0 Shadow DOM 原生穿透**：用 chrome-only 的 `Element.openOrClosedShadowRoot`（`dom/webidl/Element.webidl`，`Func="Document::IsCallerChromeOrAddon"`，页面脚本不可见、不触碰 `attachShadow.toString()`）。在特权侧（新 BiDi 命令 / 复用 `browsingContext.locateNodes`）遍历，**替换掉 `bidi.py` 现有的 `attachShadow→open` 猴补丁**。

### 框架侧（browser_controller，纯 Python 不编译）
- `drivers/bidi.py`：`Raw` 逃生舱已能直接 `b.run("moz:fingerprint.setContextOverrides", {...})`——**零改动**。
- `browser.py::new_context`（当前 164–168 行硬拒 BiDi）：改成分支——CDP 走 `Fingerprint.setContextOverrides`、BiDi 走 `moz:fingerprint.setContextOverrides`，共用同一 JSON 画像契约。
- （可选）深度查找 `find_deep`/`click_deep` 的 BiDi 实现从猴补丁切到原生穿透命令（配合 P1-0）。

## 分阶段实施（每阶段独立可编译 + fp_verify 回归 gate，改动打 `//BROWSER_FINGERPRINT` 标记便于 rebase）

| 阶段 | 目标 | 验证 gate |
|---|---|---|
| **P0 环境** | 拉 152.0.5 tarball + `./mach bootstrap` + stock `./mach build`（等 Chrome 让核）+ BiDi 连通冒烟（`browser_controller` BiDi 驱动连自编 Firefox） | 自编 Firefox 起得来、BiDi `session.new` 通 |
| **P1 管线证明 ★关键** | 新增 BiDi `moz:fingerprint` 模块骨架 + `BrowsingContext::FingerprintProfile` synced field + SessionData 接线 + **1 个维度**（UA 或 platform）端到端 | 该维度在**主 frame + 跨进程 OOPIF** 都被画像覆盖 |
| **P2 标量面** | userAgent/platform/oscpu/hardwareConcurrency/languages/locale/timezone(per-context 化)/screen/referrer | 主/OOPIF 全绿，locale 与 language 一致 |
| **P3 WebGL 标量** | vendor/renderer/extensions | 主/OOPIF 绿 |
| **P4 Firefox 4 反检测点** | webdriver/visibility/hasFocus/shadow-pierce（照 Playwright patch） | webdriver=false、headless/后台下 hasFocus=true·hidden=false·visible、closed shadow 原生定位到且页面探测不到 |
| **P5 读回面 noise** | canvas(getImageData/toDataURL/toBlob)+webgl readPixels+audio(offline/analyser) 的 `readbackSeed` murmur 微扰 + 纯色/静音走 native | 三态：有seed≠无seed、异seed异、同seed稳；纯色精确原值 |
| **P6 读回面 replay** | 上述读回点加 `*Replay` 键（从云机 `~/chromium/src` 对应 7 文件 1:1 抄值编码，按调用序取模） | 回放值 = 采集值、跨会话稳定 |
| **P7 worker 全覆盖** | dedicated/shared/service worker 读取点从 WorkerLoadInfo 快照读画像（Firefox 无 BC 的额外工作量） | 三种 worker 的 platform/tz/locale/canvas 全绿 |
| **P8 收尾+回归** | SessionData 覆盖未来 frame/新进程/持久化打磨 + `browser.py::new_context(fingerprint=)` BiDi 分支 + fp_verify 全维度×全上下文回归 | 检测页 `inconsistencies=0`、per-context 继承/独立/隔离三判定 PASS |

**节奏建议**：先只做 **P0+P1** 把传输骨架跑通（最关键），再定后续。整体是几十个编译周期的长工程。

## 验证

- **fp_verify_firefox.py**（照 `C:\Users\PokerS\Desktop\开发文档\fp_verify_selfbuilt.py` 改）：用 `browser_controller` BiDi 驱动启动自编 Firefox → 下发画像 → 主 frame / 跨站 OOPIF / worker 各取值核对 + 记请求头。
  - ⚠️ **Firefox 无 `--host-resolver-rules`**：造跨站 OOPIF 改用云机 `/etc/hosts`（`a.test`/`b.test`→127.0.0.1）或本地双 host server；Fission 靠跨 eTLD+1 iframe 触发。
  - ⚠️ 安全上下文：Firefox 用 `about:config` pref（如 `dom.securecontext.allowlist`）或 localhost/https，替代 Chromium 的 `--unsafely-treat-insecure-origin-as-secure`。
- **4 反检测点专项**：BiDi 连接下 `navigator.webdriver===false`；headless + 后台标签下 `document.hasFocus()===true`、`document.hidden===false`、`visibilityState==='visible'`；页面内 `Element.prototype.attachShadow.toString()` 为原生串（无猴补丁痕迹）且 closed shadow 里的元素能被框架定位/点击。
- **检测页**：真机 `secdev.solvermarket.com/fp-*` 类页面看 `inconsistencies=0`（复用 Chromium 侧的实战检测习惯）。

## 风险 / 难点

- **worker 传递链**：Chromium 靠 RendererPreferences 直达 worker，Firefox worker 无 BrowsingContext，需自建 WorkerLoadInfo/ClientInfo 快照链（P7 的主要工作量）。
- **per-context 时区**：Firefox 现状 `TZ=UTC` 是进程级环境变量，必须改成 BC 字段 + JS 引擎 per-realm override，且渲染进程不跨 context 复用的前提要确认（同 Chromium §12 风险）。
- **Fission OOPIF 字段广播**：BC synced field 需在合适祖先 BC 或每个 BC 设值 + SessionData 兜「未来新建/新进程」上下文。
- **mach build 抢核**：需与在跑的 Chrome 发布构建错峰，或 `-jN` 降并发（61G 内存、Swap 0，link 峰值注意）。
- **rebase 维护**：改动集中 + `//BROWSER_FINGERPRINT` 标记，便于随 Firefox 版本迁移。

## 附录：Firefox 版 JSON 画像契约

**保留键**（与 Chromium 对齐，**去掉全部 UA-CH**）：`userAgent`、`platform`、`oscpu`、`hardwareConcurrency`、`acceptLanguages`、`locale`、`timezone`、`screenWidth`/`screenHeight`、`webglVendor`/`webglRenderer`/`webglExtensions`、`referrer`、`readbackSeed`。

**读回面 replay 键**（云机 `~/chromium/src` 侦察确认的值编码，全部是 JSON 数组、按调用序取模回放）：
- `canvasDataReplay` = RGBA 字节数组的列表（getImageData）
- `canvasUrlReplay` = dataURL 字符串列表（toDataURL）
- `canvasBlobReplay` = base64 图字节列表（toBlob，`canvas_async_blob_creator.cc`）
- `glReadReplay` = base64(RGBA 字节) 列表（readPixels）
- `audioReplay` = 采样列表（OfflineAudioContext，覆盖各声道）
- `analyserFloatReplay` / `analyserByteReplay` = 浮点/字节列表（AnalyserNode）

三态优先级：`*Replay`（FindList，按调用序取模）> `readbackSeed`（murmur 微扰）> native（纯色/静音精确原值）。对应 Chromium 源 7 文件：`canvas2d/base_rendering_context_2d.cc`、`html/canvas/html_canvas_element.cc`、`html/canvas/canvas_async_blob_creator.cc`、`webgl/webgl_rendering_context_base.cc`、`webaudio/offline_audio_context.cc`、`webaudio/analyser_node.cc`（+ worker 分支）。
